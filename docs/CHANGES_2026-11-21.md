## 2. Bug: the action agent's proposals were thrown away

In that run the action agent's output was dropped in 140 of 171 cases, and no search or
quarantine was ever proposed. The model had chosen the right three actions.

* **Cause.** `OllamaClient` asks for JSON mode, which permits one JSON object and no bare list.
  The prompt asked for a list. The model answered with one object that had the key `action`
  three times; the parser kept the last value, the object failed validation, and the whole
  answer became "no proposal". Only single-action answers (a `notify` for a suspicious verdict)
  got through. The stub never showed this because the stub files contain lists.
* **Fix** (`phishgate/agents/action_agent.py`). The prompt now asks for `{"actions": [...]}`.
  `parse_proposals()` reads that shape, a bare list, a single action and the merged object
  seen on the server, and validates each action on its own: a malformed action is dropped,
  the others are kept. Nothing is repaired; the gate still checks every proposal.
* **Checked** with the local pilot model (`qwen2.5:1.5b`): it now returns the object with
  several actions. Not yet re-run on the server.

The analysis-side numbers in section 1 do not depend on this bug.

## 3. Evaluation script (`scripts/evaluate.py`)

New keys in the result:

* `defence_comparison`: how many attack mails would be closed if the model's label were
  trusted, and how many are closed with the verifier; next to it what happened to the benign
  mails. This is the "with and without the defence, with clean accuracy beside it" pair the
  mid-check asks for.
* `by_language`: the same outcome counts for Korean and English.
* `actions_proposed`, `action_agent_by_label`, `actions_done`: what the action agent asked
  for, how many cases got no proposal, what ran.
* `refusal_reasons`: why the gate refused. In a full run most refusals are
  `max_notify_per_hour reached`: the 10-messages-per-hour limit doing its job while 360 cases
  run in half an hour. A message refused for the limit had already passed the content checks.

## 4. Other things found on the server

* `bom.yaml` describes Hugging Face AWQ weights for vLLM; the run used Ollama's GGUF build.
  The team has to pick one serving stack before the BOM can be filled in and checked.
