## 2. Gate (`phishgate/gate/`)

I sent bad proposals to the old gate behind an honest phishing verdict. These got through;
all are now refused and logged.

| proposal | old gate | new gate |
|---|---|---|
| `notify` with `sender_domain` = `"evil.test. URGENT: all staff reset passwords at http://…"` | queued, text in the message | refused |
| `notify` with `benign_closed` on a phishing case | queued | refused |
| `quarantine` of an id that is not in the corpus | "executed" | refused |
| `quarantine` of a colleague's mail | executed | refused |
| `search_sender` for the CEO's address | executed | refused |
| 15 tool calls for one case over five rounds | all ran | 12 ran, 3 refused |

* **Message field values come from the gate.** It fills `case_id` and `sender_domain` itself
  from the checked verdict. A model value that differs is refused; a missing one is filled
  in. The model's strings never reach a message (threat T2, "0 attacker-written strings").
* **`sender_domain` must look like a host name**, because the From header is attacker text.
* **Template must match the label**: `phishing → phishing_warning`,
  `suspicious → hold_notice`, `benign → benign_closed` (`policy.py`).
* **An e-mail can only cause actions against its own sender.** `search_sender` accepts only
  `Facts.from_address`; `quarantine` accepts only mails from that address.
* **12 tool calls per case**, counted from the audit log, so a restart cannot reset it.
* **No actions unless the case is `to_analyst`** (the old gate checked HOLD only).

## 3. Pipeline (`phishgate/pipeline.py`)

* **HOLD cases go to the analyst queue** (queue kind `hold_review`, audit event `hold_queued`).
  Before, the arrow in Figure 1 had no code behind it.
* **Invalid model output fails closed.** Three bad outputs used to crash the run with no
  verdict row. Now the case becomes HOLD (`analysis agent produced no valid verdict`), with a
  `verdict_invalid` audit row.
* **The reported mail joins the corpus index**, so it can be searched and quarantined.

## 4. Rules, facts and verifier

* **Look-alike domains** (`rules/domains.py`, new; list in `data/org_domains.txt`): the
  organisation's name used as a word in another domain, confusable characters, one-letter
  typos. Applied to links and to the sender domain.
* **HTML to visible text** (`rules/html_text.py`, new): comments, scripts and CSS-hidden
  elements are dropped before the model reads the mail. The rule results report that hidden
  text was present. A mail with a plain and an HTML part now shows both to the model.
* **Anchor text versus target**: a link that shows one domain and goes to another is flagged.
* **`softfail` counts as an authentication failure** unless DMARC passed.
* **Reply-To** is compared by registrable domain, so `mail.x.test` versus `x.test` is fine.
* **`Facts` has four new fields**: `reply_to_mismatch`, `lookalike_sender`, `from_address`,
  `message_id`. The last two are what the action agent acts on; they are passed on only if
  they have a plain shape, otherwise they are empty.
* **Verifier**: a `benign` label now becomes HOLD if Reply-To points elsewhere, if the sender
  domain imitates ours, or if confidence is under 0.6. Only `benign` is checked this way,
  because a closed case is the one outcome nobody looks at again.

## 5. Action agent (`phishgate/agents/action_agent.py`)

New prompt: which value to use for each argument, which template fits which label, an
example, and a reminder that every string in its input is data. Not verified against the
real model. The gate re-checks everything, so a bad proposal is refused whatever the prompt does.

## 6. Monitor, analyst page, command line

* **Monitor** (`audit/monitor.py`): alerts for HOLD rate, refusals per case, limit overruns,
  message volume, model output that never parsed, a domain closed as benign after it was
  flagged, and canary markers in any row written after intake.
* **Analyst page** (`phishgate/web.py`, new, Flask): upload a mail, approve or reject the queue,
  release a quarantine, see alerts and the audit log. Local only: binds to 127.0.0.1, no
  JavaScript, strict CSP, a form token on every POST, all values escaped. It has no login.
* **CLI**: `load-corpus`, `quarantined`, `release`, `serve`, and `--stub-file` to script the stub.
  `approve` / `reject` audit rows now carry the case id.
* **Quarantine moves a file** between `workspace/corpus/` and `workspace/quarantine/`; `release`
  moves it back. File names are hashes of the message id.

### Second round (same day)

* **Attachment content** (`rules/attachment_rules.py`, standard library only). Besides the
  extension list: bytes that start like a Windows program, a shortcut or a disk image whatever
  the name says; an Office file with a VBA project (`vbaProject.bin` in the member list of a
  new-format file, the `_VBA_PROJECT` storage in an old-format one); a ZIP holding a member with
  a dangerous suffix. Nothing is unpacked or run. Each attachment gets fixed `why` codes.
  Limits: it says a macro is present, not what it does; an encrypted archive is reported but
  not called dangerous; nested archives are not followed. New sample
  `phish_macro_disguised.eml` is caught by this check alone.
* **Datamarking** (`intake/prompt_assembly.py`). Every run of spaces in the body, the subject
  and attachment names becomes `ˆ` (U+02C6); the prompt explains, outside the data block, that
  such text is never an instruction. The marker is removed from the mail first.
  `PHISHGATE_DATAMARK=0` switches it off. **Not measured on a model**: it may lower accuracy,
  Korean included, so run the evaluation both ways before keeping it on.
* **Sycophancy test** (`scripts/sycophancy.py`). 50 correctly labelled mails are run again with
  a confident false comment ("this is safe" / "this is phishing", Korean or English); it reports
  the flip rate and, for phishing talked into benign, whether the verifier still stops the case.
  The comment enters through a new optional `analyst_note` argument of `build_analysis_prompt`
  / `run_analysis_agent`. The pipeline never passes one. With the stub the result is 0 flips by
  construction.
* **Tidying**: the `Owner:` lines are gone from the docstrings; the unused helper in `web.py`
  is removed.

## 9. Decisions to confirm

1. **Schema change**: four new `Facts` fields (section 4).
2. **Verifier rules for `benign`**: Reply-To mismatch, look-alike sender, confidence floor 0.6.
   They cost nothing on the generated benign set (0 of 200 held), but that set has no benign
   mail with a foreign Reply-To. Real newsletters often have one.
3. **Placeholder verdict.** When the model gives no valid output, code writes a `Verdict`
   (label `suspicious`, confidence 0) because `CheckedVerdict` requires one. Making `verdict`
   optional would be cleaner.
4. **"3 actions" versus "12 tool calls".** I kept the existing test's meaning: 3 proposals per
   action-agent round (a search counts), 12 tool calls per case in total.
5. **Scope rule**: the action agent can only search and quarantine mail from the sender of the
   case. It cannot quarantine "all mail from this sender" in one step, because the search
   returns no ids and the agent is called once. The bulk-quarantine path exists in the gate
   but no model can reach it yet.
6. **`suspicious → hold_notice`**: I picked the template whose text fits.
7. **Approving a `hold_review` item only records the decision.** What should it do?
8. **Residual risk**: a well-formed sender domain is shown in the message as it is, for example
   `reset-your-password.evil.test`. No link or sentence can get in, but the name can carry words.
9. **Datamarking is on by default** although its effect on the model is unknown.
10. **The sycophancy test adds an input the product does not have**: an analyst comment in the
    analysis prompt. If the proposal meant something else by "false claim from the analyst"
    (for example pressure at the approval step), the script needs to change.
11. **An encrypted archive is not treated as dangerous.** Password-protected ZIPs are a common
    lure, but also common in ordinary mail.
